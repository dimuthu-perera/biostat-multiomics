## H1 — HIGH — demonstrated defect: relationship-target mismatch bypasses raw worksheet preflight

**Source references:**

- `correlation_tool/io.py::_preflight_xlsx_worksheet_xml`, starting at line 275; worksheet selection at lines 285–287.
- `correlation_tool/io.py::_read_xlsx`, starting at line 343.
- Installed openpyxl: `reader/workbook.py::WorkbookParser.find_sheets` and `reader/excel.py::ExcelReader.read_worksheets`.

Preflight selects archive members using:

```python
name.startswith("xl/worksheets/") and name.endswith(".xml")
```

Openpyxl instead follows the workbook's sheet relationship and opens `rel.target`. The candidate never verifies that every worksheet openpyxl will load belongs to the set it preflighted.

### Exact reproduction

The evidence archive contains two small self-contained XLSX fixtures:

- `alternate_worksheet_hidden_formula.xlsx` — samples in rows;
- `alternate_worksheet_columns.xlsx` — samples in columns.

They were generated by the independent harness's `alternate_part()` as follows:

1. Create an ordinary worksheet containing four samples and one feature. One measurement cell contains `=123`.
2. Add merge metadata covering that formula as a non-anchor cell: `B2:B3` for the samples-in-rows fixture, `B2:C2` for samples-in-columns.
3. Store this actual worksheet at `xl/data/matrix.xml` and make the workbook's worksheet relationship target `/xl/data/matrix.xml`. Add the matching worksheet content-type declaration.
4. Leave a harmless, unreferenced empty worksheet at `xl/worksheets/sheet1.xml`.

Preflight scans the harmless member. Openpyxl loads the relationship target and erases the formula during merged-cell processing. These are intentionally adversarial files accepted by the implementation; no claim is made that ordinary researcher exports commonly have this structure.

Minimal execution using the supplied rows fixture:

```python
import pandas as pd
from correlation_tool import (
    load_matrix, inspect_run, analyze_validated_run,
    create_acknowledgement, DatasetDeclaration,
    StudyDesignDeclaration, CorrelationConfig,
)

a = load_matrix("alternate_worksheet_hidden_formula.xlsx")
assert pd.isna(a.loc["S1", "x"])  # original cell was a formula
b = pd.DataFrame({"y": [4., 3., 2., 1.]}, index=["S0", "S1", "S2", "S3"])
d = DatasetDeclaration("metabolomics", "quantitative")
r = inspect_run(a, b, d, d, StudyDesignDeclaration("independent"),
                CorrelationConfig(method="pearson"))
completed = analyze_validated_run(r, acknowledgement=create_acknowledgement(r))
assert completed.results.loc[0, "n_pairwise"] == 3
assert completed.results.loc[0, "status"] == "ok"
```

**Observed in both orientations:** preflight accepts, the original formula becomes a missing measurement, and public validated analysis completes with N=3. The generic missingness warning can be acknowledged; it does not disclose import-time deletion of a formula. This violates the declared requirement to reject formulas and merges before workbook construction.

**What this establishes:** a completed analysis can be generated from a matrix whose original occupied cell was discarded by an unvalidated structure. The archive-byte limits still run; ordinary post-construction dimensions are still checked. This finding is not a claim that those byte checks vanished. The same routing gap skips the raw coordinate/merge checks for the loaded worksheet; large merge expansion remains a source-inspected consequence of that omission. No destructive resource-exhaustion workbook was executed.

### Smallest correction

Make the preflight set and the loader's worksheet set identical. Resolve the actual workbook sheet relationships before workbook construction, and preflight every worksheet target that will be loaded. Alternatively, retain a strict supported-path contract and **reject** any referenced worksheet target outside the validated set. Supporting arbitrary new layouts is not required.

Preserve the current formula/merge rejection and archive budgets. Do not silently unmerge or recover hidden values. Add both supplied fixtures as regressions asserting a structured rejection **before** `load_workbook` is invoked. Once this mismatch is closed, the remaining statistical and registered-callback checks from this audit can serve as the regression baseline.

## Gradio lifecycle: tested through actual registered dispatch

The independent harness obtained function indices from `app.demo.fns` and invoked the registered `inspect_ui`, `analyze_ui`, and `invalidate_ui` using:

```python
await app.demo.call_function(index, list(processed_inputs), requests=real_request)
```

Copying the processed-input list is necessary because Gradio's injection helper inserts the request into that list. No internal callback was substituted for the registered wrapper in these tests.

**15 controlled interleavings passed:**

| Paused stage | Same-session input invalidation | Same-session reinspection | Invalidation in other session |
|---|---|---|---|
| Analysis-time parsing | Obsolete output suppressed | Suppressed | Original valid run completes |
| Correlation computation | Suppressed | Suppressed | Completes |
| Bundle writing | Suppressed | Suppressed | Completes |
| Preview sorting | Suppressed | Suppressed | Completes |
| Internal callback finished, registered wrapper not yet returned | Suppressed | Suppressed | Completes |

For suppressed cases, the registered callback returned an empty preview and no download. An additional test invalidated an initial inspection while its parsing was paused: it returned no stored inspection, no download, and an unchecked acknowledgement.

The real session hashes were used, and the fallback `__direct_callback_session__` key was absent. The previous request-injection mismatch and demonstrated late-preview race did not reproduce. Source also retains obsolete-bundle cleanup.

This verifies the requested registered callback behavior under those interleavings. It is not a claim of exhaustive browser/network rendering behavior; broad cross-browser testing remains separate release work and is not used to block the oracle here.

## Versions, provenance and one non-blocking test defect

**LOW — demonstrated test-maintenance defect:** the supplied suite produced **57 passes and 1 failure**, rather than the `VALIDATION.md` claim of 58 passes. `tests/test_reaudit_regressions.py::test_spearman_policy_thresholds_cannot_be_lowered` expects the exception text `fixed Spearman inference policy`, but `CorrelationConfig.__post_init__` now says `The supported reference policy is ...`.

The unsafe override correctly raises `ValueError`; the failure is the stale message regex, not an inference-policy regression. Update the assertion or retain a stable error phrase, then refresh the validation record from the actual archive. This alone would not block statistical-oracle readiness.

## Acceptance decision

Close **H1** by proving that every loaded worksheet was preflighted, with both orientation fixtures rejected before workbook construction. Correct the stale regression assertion and rerun the focused checks. No statistical redesign, distance correlation, transformation policy change, licensing decision, retention redesign or full cross-browser CI is required to fix the demonstrated blocker.
